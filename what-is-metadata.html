Metadata: what it is and why it matters

Metadata is data about a file, not the content itself. The photo is the content. The phone model, timestamp and GPS position stored inside it are the metadata.

Most people never look at it. That is why it is worth looking at.

Where it hides

  • Images: EXIF tags such as camera or phone model, date and time, GPS coordinates, editing software
  • PDFs: title, author, creator and producer software, creation and modification dates
  • Office documents: author, last modified by, revision details

Why it matters for pentesting

In recon, public files are a free source of information. Documents a company publishes often carry more than it meant to share.

  • Author fields give real names and hint at the username format
  • Creator and producer fields show what software was used, sometimes with versions
  • Folder paths and machine names can point at internal naming
  • Photos can reveal locations and devices

None of this needs an exploit. It is just reading what was already given away.

Why it matters for the blue team

  • Investigations: timestamps and tool fields help build a timeline and show where a file came from
  • Spotting oddities: dates or software that do not fit the story of a file are worth a closer look
  • Prevention: clean files before they leave the organisation, so you do not leak what an attacker would collect

Same data, opposite uses. I wanted a tool that does both: read what a file gives away, then strip it before sharing.

MetaClean

MetaClean is a small Python command-line tool that inspects metadata in common images and PDFs and writes cleaned copies. The code is on GitHub: github.com/Hardcore-Blue/metaclean.

metaclean inspect photo.jpg
metaclean inspect ./documents --format json --output report.json
metaclean clean photo.jpg --output cleaned/photo.jpg

Inspecting

The inspect command checks the file extension and picks the matching reader. It uses Pillow for images and pypdf for PDFs.

  • Images: format, dimensions, color mode, frame count, EXIF tags and image-container fields
  • PDFs: page count, encryption status and document information fields such as title or author
  • Output: readable text, or JSON or CSV reports

Cleaning

The clean command writes a new file and leaves the source untouched.

For images, it decodes the pixels and re-encodes them without EXIF, ICC profiles, comments or container metadata. It applies the EXIF orientation to the pixels first, so the image keeps its displayed rotation. Animated images are rejected to avoid dropping frames.

For PDFs, it copies the pages into a new PDF without the document information dictionary. Encrypted PDFs are rejected.

Limits

MetaClean is intentionally conservative. It skips existing output files unless you ask for overwriting, and it reports files it cannot process.

  • It does not redact text or images on PDF pages
  • It cannot guarantee every possible metadata structure is removed
  • Re-encoding can change image size or color slightly

Always inspect the cleaned copy before you share it. This is not a forensic sanitisation guarantee.

Python techniques I used

  • argparse: defines the inspect and clean commands, their options and the help text
  • Small, focused functions: inspection, cleaning, file discovery and report writing live in core.py, and the CLI in cli.py ties them together
  • Type hints: annotations like Path, list[dict[str, Any]] and -> int document inputs and outputs
  • pathlib: handles paths, extension checks, recursive searches and output locations
  • Context managers: with blocks close image files and PDF output streams, even when an error occurs
  • Defensive error handling: one bad file does not stop a batch scan, and exit codes tell scripts whether it worked
  • Structured output: results are Python dictionaries, serialised with the json and csv modules
  • Packaging: pyproject.toml declares dependencies and exposes metaclean as an installable command

One design choice I like: inspection and cleaning are separate operations. That makes it easier to add more file formats later without tying every format to one large command function.
